# 第3週: BigQuery で生データが見える

GCS に貯まった生データを BigQuery に入れ、SQL で見えるようにする週。

```
#41 ADR 0005（ロード方法を決める）→ 実装（データセット・テーブル・DTS の転送設定）
```

## #41 ADR 0005: GCS → BigQuery のロード方法

| 学んだこと | 中身 |
|---|---|
| 入れ方は4種類 | バッチロード（無料）、ストリーミング（有料）、外部テーブル（入れずに GCS を直接読む）、Data Transfer Service（バッチロードを定期実行してくれるマネージドサービス） |
| バッチロードは無料 | 共有スロット `default-pipeline` で動くため。費用がかかるのは入れた後のストレージ（10 GiB まで無料）とクエリ（1 TiB まで無料） |
| DTS の APPEND は「更新されたファイルだけ」 | 前回の成功以降に `updated` が新しいファイルを読む。同じ5分枠を上書きすると、もう一度読まれて重複する → dbt で除く |
| 鮮度は用途で決める | ダッシュボードなら1時間遅れで十分。速さを求めると、取得とロードが結びついて壊れやすくなる |
| 正本と作業用を分ける | 正本は GCS に残し、BigQuery の raw はパーティションの有効期限（30日）で消す。消しても入れ直せる |
| 先にデータ量を測る | 1回約96行、1日約2.8万行・約13 MB。無料枠に対して十分小さいと分かってから選択肢を比べた |

ADP: データの準備と取り込み（バッチロード・DTS・外部テーブルの違い）
